Vault KMS for Kubernetes — Raw Commands Reference

Every command needed to set up and run the lab, written out verbatim — no Makefile abstraction. Use this alongside overview.html or as a step-by-step audit trail.

Environment & Shared Variables

All commands below assume these variables are set in your shell. Export them once at the start of a session.

# Vault address — Vault runs on your machine via Docker Compose export VAULT_ADDR="http://127.0.0.1:8200" # Set after vault operator init (see Section 1) export VAULT_TOKEN="<root-token>" # Kind container name — used for docker exec commands export KIND_NODE="vault-kube-kms-control-plane" # Docker bridge gateway — how the kind node reaches Vault on your machine # Detect it automatically: VAULT_HOST=$(docker network inspect bridge \ --format '{{range .IPAM.Config}}{{.Gateway}}{{end}}' 2>/dev/null \ || echo "172.17.0.1") export VAULT_HOST
1

Start Vault Enterprise

Start the container
# From the repo root VAULT_LICENSE=$(cat License/vault.hclic) \ docker compose --profile enterprise up -d # Wait until Vault is reachable until vault status >/dev/null 2>&1; do sleep 1; done
Initialize (first time only)
# 5 key shares, threshold 3 — saves keys to .vault-init.json vault operator init -key-shares=5 -key-threshold=3 \ -format=json > .vault-init.json # Extract the root token export VAULT_TOKEN=$(jq -r '.root_token' .vault-init.json)
Unseal (3 keys required)
jq -r '.unseal_keys_b64[0]' .vault-init.json | xargs vault operator unseal jq -r '.unseal_keys_b64[1]' .vault-init.json | xargs vault operator unseal jq -r '.unseal_keys_b64[2]' .vault-init.json | xargs vault operator unseal # Confirm sealed=false and ha_enabled=false vault status
2

Configure Vault — Transit, Policy, AppRole

Enable secrets and auth engines
# Transit secrets engine at default path transit/ vault secrets enable transit # AppRole auth method vault auth enable approle # File audit log inside the container (volume-mounted to ./data/) vault audit enable file file_path=/vault/logs/audit.log
Create the Key Encryption Key (KEK)
# AES-256-GCM96 is the default and the right choice for envelope encryption vault write -f transit/keys/kms # Confirm it exists vault read transit/keys/kms
Write the KMS policy
# encrypt and decrypt both require ["update","create"] — ["update"] alone causes silent failures vault policy write transit-encrypt-decrypt - <<'EOF' path "transit/encrypt/kms" { capabilities = ["update", "create"] } path "transit/decrypt/kms" { capabilities = ["update", "create"] } path "transit/keys/kms" { capabilities = ["read"] } path "sys/license/status" { capabilities = ["read"] } EOF
Create the AppRole
# Create the role — role_id must be set explicitly so --approle-role-id=lab-kube-kms works vault write auth/approle/role/kube-kms \ role_id="lab-kube-kms" \ token_policies="transit-encrypt-decrypt" \ token_ttl=1h \ token_max_ttl=4h \ secret_id_num_uses=0 # Confirm role-id is exactly "lab-kube-kms" vault read auth/approle/role/kube-kms/role-id # Generate a secret-id (save this — it is needed by the plugin) vault write -f auth/approle/role/kube-kms/secret-id
Save the secret-id for use in the kind node
# Store to a local file so deploy-kms-binary.sh can copy it in SECRET_ID=$(vault write -force -format=json \ auth/approle/role/kube-kms/secret-id \ | jq -r '.data.secret_id') mkdir -p .lab-state echo "$SECRET_ID" > .lab-state/approle-secret-id chmod 0400 .lab-state/approle-secret-id
3

Create the Kind Cluster

Create cluster with encryption-config volume mount
# k8s/kind-config.yaml mounts /etc/kubernetes/encryption-config.yaml into the node kind create cluster \ --name vault-kube-kms \ --config k8s/kind-config.yaml \ --image kindest/node:v1.33.1
Install etcdctl inside the kind node
# etcdctl is NOT installed on your host — only inside the kind container docker exec "$KIND_NODE" apt-get update -qq docker exec "$KIND_NODE" apt-get install -y --no-install-recommends etcd-client
4

Build and Deploy the vault-kube-kms Plugin

Clone the upstream source
# Skip if the directory already exists (e.g. from a zip archive) if [ ! -d /tmp/vault-kube-kms-src ]; then git clone https://github.com/hashicorp/vault-kube-kms \ /tmp/vault-kube-kms-src fi
Cross-compile for Linux amd64 (kind nodes are always Linux amd64)
cd /tmp/vault-kube-kms-src CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \ go build -o .lab-state/vault-kube-kms ./main.go
Why CGO_ENABLED=0
The binary runs inside the kind node (a Docker container). CGO produces glibc-linked binaries that may not match the container's libc version. A fully static binary has no runtime dependencies.
Copy binary and secret-id into the kind node
# /opt/kms/ is used instead of /tmp because /tmp is a tmpfs inside kind nodes # and docker cp writes are not visible to running processes there. docker exec "$KIND_NODE" mkdir -p /opt/kms docker cp .lab-state/vault-kube-kms "${KIND_NODE}:/opt/kms/vault-kube-kms" docker exec "$KIND_NODE" chmod +x /opt/kms/vault-kube-kms docker cp .lab-state/approle-secret-id "${KIND_NODE}:/opt/kms/approle-secret-id" docker exec "$KIND_NODE" chmod 0400 /opt/kms/approle-secret-id
Start the plugin
# Replace <VAULT_HOST> with the actual Docker bridge gateway IP docker exec -d "$KIND_NODE" \ /opt/kms/vault-kube-kms \ --vault-key-path=transit/keys/kms \ --vault-address="http://${VAULT_HOST}:8200" \ --approle-role-id=lab-kube-kms \ --approle-secret-id-path=/opt/kms/approle-secret-id \ --tls-skip-verify \ --metrics-port=9090 \ --health-port=8081 \ >> /var/log/kms.log 2>&1
Wait for the Unix socket to appear
# The socket must exist before the API server is patched for i in $(seq 1 30); do docker exec "$KIND_NODE" \ test -S /tmp/vault-kube-kms.socket 2>/dev/null && echo "Socket ready" && break sleep 2 done
Check /readyz
# Plugin health — must return 200 before proceeding docker exec "$KIND_NODE" curl -sf http://127.0.0.1:8081/readyz \ && echo "Plugin ready" \ || echo "Plugin not ready"
5

Enable Encryption on the API Server

Patch the kube-apiserver static pod manifest
# The manifest lives at /etc/kubernetes/manifests/kube-apiserver.yaml inside the node # Use awk to insert the two flags on the line immediately after '- kube-apiserver'. # The awk command runs entirely inside the container — no heredoc / stdin passing needed. docker exec "$KIND_NODE" bash -c ' MANIFEST=/etc/kubernetes/manifests/kube-apiserver.yaml if ! grep -q encryption-provider-config "$MANIFEST"; then awk "/- kube-apiserver/{print; print \" - --encryption-provider-config=/etc/kubernetes/encryption-config.yaml\"; print \" - --encryption-provider-config-automatic-reload=true\"; next}1" \ "$MANIFEST" > /tmp/apiserver-patched.yaml mv /tmp/apiserver-patched.yaml "$MANIFEST" echo "Manifest patched" else echo "Already patched — skipping" fi '
Wait for the API server to restart (up to 5 minutes)
# kubelet detects the manifest change and restarts the API server static pod echo "Waiting for API server restart..." sleep 10 for i in $(seq 1 60); do kubectl cluster-info >/dev/null 2>&1 && echo "API server ready" && break echo " attempt $i/60..." sleep 5 done

Verify Encryption (kms-verify)

Write a test secret via the Kubernetes API
kubectl create secret generic lab-secret \ --from-literal=password=supersecretvalue \ --namespace default
Read the raw etcd bytes — must show ciphertext
ETCD_CERTS_DIR="/etc/kubernetes/pki/etcd" docker exec "$KIND_NODE" bash -c " ETCDCTL_API=3 etcdctl \ --endpoints=https://127.0.0.1:2379 \ --cacert=${ETCD_CERTS_DIR}/ca.crt \ --cert=${ETCD_CERTS_DIR}/server.crt \ --key=${ETCD_CERTS_DIR}/server.key \ get /registry/secrets/default/lab-secret "
Expected output begins with k8s:enc:kms:v2:vault-kube-kms:. The plaintext value supersecretvalue must NOT appear.
Confirm the plaintext is absent from etcd
docker exec "$KIND_NODE" bash -c " ETCDCTL_API=3 etcdctl \ --endpoints=https://127.0.0.1:2379 \ --cacert=${ETCD_CERTS_DIR}/ca.crt \ --cert=${ETCD_CERTS_DIR}/server.crt \ --key=${ETCD_CERTS_DIR}/server.key \ get /registry/secrets/default/lab-secret \ | grep -c 'supersecretvalue' " || echo "PASS: plaintext not found in etcd"
Read back via Kubernetes API (decrypted by Vault)
kubectl get secret lab-secret \ --namespace default \ -o jsonpath='{.data.password}' \ | base64 -d && echo

Zero-Downtime Key Rotation (kms-rotate)

Rotate the Transit KEK — one command
# Vault creates a new key version; the plugin picks it up via the KMS v2 Status RPC vault write -f transit/keys/kms/rotate # Confirm the new version is active vault read transit/keys/kms | grep -E 'latest_version|min_decryption'
Re-encrypt all existing secrets with the new key
# Forces every secret through a write cycle so etcd entries use the new KEK version kubectl get secrets --all-namespaces -o json \ | kubectl replace -f -
Verify the new ciphertext uses the updated key version
# Read the key — min_decryption_version should still be 1 (old data still readable) vault read transit/keys/kms # Write a new secret and read it back — should succeed with the new key kubectl create secret generic lab-post-rotate \ --from-literal=value=after-rotation kubectl get secret lab-post-rotate \ -o jsonpath='{.data.value}' | base64 -d && echo

Resilience Under Vault Outage (kms-failover)

Stop Vault
docker compose --profile enterprise stop
Try to read an existing secret (should succeed via DEK-seed cache)
kubectl get secret lab-secret \ --namespace default \ -o jsonpath='{.data.password}' \ | base64 -d && echo # Expected: supersecretvalue — the API server uses its in-memory DEK cache
Try to write a new secret (should fail — Vault unreachable)
kubectl create secret generic lab-during-outage \ --from-literal=value=should-fail # Expected: error — the API server cannot encrypt a new DEK seed without Vault # The 3-second KMS v2 timeout fires, and the write is rejected
Restart Vault and unseal
docker compose --profile enterprise start # Wait for Vault to be ready until vault status >/dev/null 2>&1; do sleep 1; done # Unseal (always required after restart — Vault seals on shutdown) jq -r '.unseal_keys_b64[0]' .vault-init.json | xargs vault operator unseal jq -r '.unseal_keys_b64[1]' .vault-init.json | xargs vault operator unseal jq -r '.unseal_keys_b64[2]' .vault-init.json | xargs vault operator unseal vault status | grep -E 'Sealed|HA'
Confirm writes succeed again
kubectl create secret generic lab-post-recovery \ --from-literal=value=back-online kubectl get secret lab-post-recovery \ -o jsonpath='{.data.value}' | base64 -d && echo
9

Observability — Metrics and Audit Log (kms-telemetry)

Read the Vault audit log
# The audit log is volume-mounted from the container to ./data/logs/audit.log tail -20 data/logs/audit.log | jq ' { time: .time, type: .type, path: .request.path, op: .request.operation }'
Scrape the plugin Prometheus metrics
# Port 9090 inside the kind node — curl from within the container docker exec "$KIND_NODE" curl -sf http://127.0.0.1:9090/metrics \ | grep -E 'rpc_server_duration|rpc_server_requests'
Check plugin health endpoints
# /healthz — liveness docker exec "$KIND_NODE" curl -sI http://127.0.0.1:8081/healthz # /readyz — readiness (non-200 means new writes will fail) docker exec "$KIND_NODE" curl -sI http://127.0.0.1:8081/readyz
Tail the plugin log
docker exec "$KIND_NODE" tail -30 /var/log/kms.log
✕

Teardown

Delete the kind cluster
kind delete cluster --name vault-kube-kms
Stop and remove Vault
docker compose --profile enterprise down -v
Remove generated lab state
rm -rf .lab-state .vault-init.json data/
Note
License/vault.hclic is not removed by teardown — it is gitignored and user-managed. Re-run make bootstrap (or the commands in Sections 1–5) to start fresh.
